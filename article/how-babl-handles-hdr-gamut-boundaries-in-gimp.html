How Babl Handles HDR Gamut Boundaries in GIMP

The babl color engine serves as the underlying pixel-format translation library for GEGL and GIMP, providing high-fidelity conversions between diverse color spaces, encodings, and bit depths. To maintain high dynamic range (HDR) gamut boundaries during RGB conversions, babl relies on an unbounded floating-point architecture, linear-light intermediate transformations via CIE XYZ, and the strict avoidance of premature clipping. This ensures that extreme spectral highlights and wide-gamut colors extending beyond destination primary coordinates remain mathematically preserved rather than discarded.

Unbounded Floating-Point Arithmetic

Traditional digital imaging pipelines clamp color channel values to a normalized range of [0.0, 1.0] (or integer equivalents like 0–255), which automatically discards HDR luminance values and out-of-gamut chrominance. Babl bypasses this restriction by utilizing 32-bit and 64-bit IEEE floating-point formats in an unbounded processing model.

In this system:

  • Values greater than 1.0 represent specular highlights and dynamic ranges brighter than standard reference white.
  • Values below 0.0 represent colors that exist outside the target color space’s chromaticity triangle (negative primary values).

By permitting negative numbers and values exceeding unity, babl treats gamut boundaries as flexible coordinate markers rather than hard physical barriers.

Reference Color Space and Matrix Transformations

RGB-to-RGB conversions in babl do not convert directly between arbitrary primaries. Instead, babl linearizes the input RGB data by removing any transfer functions (gamma curves) and projects the values into an absolute reference space, typically CIE XYZ or CIE LAB, using high-precision matrix multiplication.

When converting from a wide source gamut (such as Rec.2020 or ProPhoto RGB) to a narrower destination gamut (such as sRGB):

  1. The input coordinates are converted to absolute CIE XYZ tristimulus values.
  2. The destination matrix projects these XYZ values into the target RGB coordinate system.
  3. If an input color lies outside the destination gamut, the resulting destination RGB channels will contain negative components or out-of-scale ratios.
  4. Babl stores these out-of-gamut coordinates precisely as calculated, without applying automatic clamping or arbitrary gamut mapping algorithms during basic conversions.

Preservation of Chromaticity and Round-Trip Fidelity

Because babl preserves negative numbers and unbounded values across conversions, color data retains its original chromaticity vector. An out-of-gamut color converted from a wide gamut into a narrow working space can later be converted back to the original wide gamut—or to an entirely different wide gamut—with zero loss of color information.

This non-destructive behavior is critical for GIMP’s non-destructive editing pipeline. Operations like exposure adjustments, color balancing, or tone mapping can pull out-of-gamut negative values back into visible, positive ranges without clipping artifacts or chromatic skew.

Dynamic Pipeline Generation and Numerical Precision

Babl optimizes conversions by constructing dynamic processing graphs (fish paths). It analyzes the fastest and most numerically accurate sequence of operations between formats. During these fast-path generations (often accelerated via SIMD extensions such as AVX or SSE), babl maintains 32-bit floating-point precision throughout all intermediate matrix steps. This minimizes numerical drift and rounding errors at gamut boundaries, ensuring that edge-case HDR values retain their exact physical meaning throughout the editing session.
