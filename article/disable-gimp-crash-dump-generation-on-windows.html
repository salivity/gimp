Disable GIMP Crash Dump Generation on Windows

When GIMP encounters an unhandled exception or crashes on Windows, it automatically launches an internal debugging process to capture stack traces and generate crash dump files. While useful for developers, this background operation can consume system resources, write large files to your drive, or cause the program to hang indefinitely during an exit failure. This guide explains how to disable GIMP's automated crash dump and debug report generation using in-app settings, file modification, and Windows environment adjustments.

Method 1: Disable Debug Policy in GIMP Preferences

The most direct way to stop GIMP from gathering debug information during a crash is through its internal preferences:

  1. Open GIMP.
  2. Navigate to Edit > Preferences.
  3. In the left-hand menu, click on System Resources.
  4. Scroll down to the Debugging section.
  5. Locate the Debug policy dropdown menu.
  6. Change the setting from its default to Never.
  7. Click OK to save the changes, then restart GIMP.

Setting the debug policy to "Never" stops GIMP from launching its automated backtrace generator when a fault occurs.

Method 2: Rename the Debug Tool Executable

If GIMP continues to trigger background crash handling or crashes before opening the Preferences menu, you can manually disable the executable responsible for dump generation:

  1. Close GIMP completely.
  2. Open Windows File Explorer and navigate to the GIMP installation directory (typically C:\Program Files\GIMP 2\bin).
  3. Locate the file named gimp-debug-tool.exe.
  4. Right-click the file and select Rename.
  5. Change the filename to gimp-debug-tool.exe.bak (administrator permissions will be required).

Without access to this executable, GIMP will terminate immediately upon crashing rather than launching a background process to collect diagnostic dumps.

Method 3: Disable Crash Dumps via Environment Variables

GIMP checks specific environment flags to determine its debugging behavior. You can explicitly turn off debugging routines system-wide:

  1. Press Windows Key + R, type sysdm.cpl, and press Enter to open System Properties.
  2. Go to the Advanced tab and click Environment Variables.
  3. Under the User variables or System variables section, click New.
  4. Set the Variable name to GIMP_DEBUG.
  5. Set the Variable value to no.
  6. Click OK on all windows to apply the setting.

Method 4: Check Windows Error Reporting (WER) Settings

If crash dumps are still being generated in your %LOCALAPPDATA%\CrashDumps folder, Windows itself may be capturing them:

  1. Press Windows Key + R, type regedit, and press Enter.
  2. Navigate to: HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows\Windows Error Reporting\LocalDumps.
  3. Check if a subkey named gimp-2.10.exe (or your current GIMP version) exists.
  4. If present, either delete the key or set the DumpType DWORD value to 0 to disable dump creation entirely for the application.
