How GIMP Sets Resolution for PostScript Files

When opening PostScript (.ps) files in GIMP, the program cannot natively process vector commands, so it delegates the file to an external Ghostscript interpreter to convert the vector paths into a raster pixel grid. This article explains how GIMP determines the default dimensions from PostScript bounding box metadata, how user-selected resolution (pixels per inch) calculates the final pixel canvas, and how rendering parameters like anti-aliasing affect the output quality.

Ghostscript as the Raster Image Processor

GIMP relies on Ghostscript (specifically via the file-ps or file-pdf plug-in) to parse PostScript data. Because PostScript is a page-description programming language containing vectors, fonts, and procedural instructions rather than fixed pixels, it must go through a Raster Image Processor (RIP). When you initiate an import, GIMP calls Ghostscript in the background to evaluate the document’s code and render it to a flat bitmap image suitable for GIMP’s pixel-based workspace.

Baseline Dimensions and the Bounding Box

Before applying a resolution, GIMP determines the physical size of the document. PostScript files define layout dimensions in standard typographical points, where 1 point is defined as 1/72 of an inch.

To determine the canvas boundaries, GIMP reads the document structure comments within the PostScript header:

  • %%BoundingBox: Provides integer coordinates for the lower-left and upper-right corners of the artwork.
  • %%HiResBoundingBox: Provides high-precision floating-point coordinates for the same limits.

If neither header is present, GIMP falls back to a standard page size (such as Letter or A4) defined in its environment preferences. The total width and height in points are calculated by subtracting the minimum coordinates from the maximum coordinates.

The Resolution Calculation Formula

Once the point dimensions are established, GIMP opens an import dialog allowing you to specify the rendering resolution, measured in pixels per inch (PPI) or dots per inch (DPI). By default, GIMP typically suggests 100 DPI or the display resolution configured in GIMP’s preferences.

The final pixel dimensions of the imported raster layer are calculated using the following formula:

\[\text{Pixels} = \left(\frac{\text{Points}}{72}\right) \times \text{Resolution (DPI)}\]

For example, a standard PostScript document measuring 612 × 792 points (8.5 × 11 inches) will resolve differently depending on the chosen DPI:

  • 72 DPI: 612 × 792 pixels (1 point = 1 pixel)
  • 150 DPI: 1275 × 1650 pixels
  • 300 DPI: 2550 × 3300 pixels
  • 600 DPI: 5100 × 6600 pixels

Users can either adjust the resolution field directly or enter target pixel dimensions; GIMP will automatically recalculate the corresponding DPI to maintain the aspect ratio dictated by the bounding box.

Anti-Aliasing and Subpixel Sampling

Resolution dictates only the grid density; edge clarity depends on anti-aliasing settings in the import dialog. GIMP provides separate controls for:

  • Text Anti-Aliasing: Sets the sampling rate (Weak, Strong, or None) for font rendering.
  • Graphic Anti-Aliasing: Sets the edge-smoothing intensity for vector shapes and lines.

When anti-aliasing is enabled, Ghostscript renders the PostScript code internally at a higher subpixel resolution and downsamples the result to the requested canvas resolution. This blends edge boundaries with intermediate transparency or gray values, preventing stair-stepped jagged edges on curved paths.

Best Practices for Resolution Selection

Because rasterization is a destructive, one-way conversion, the resolution set during import is permanent for that session:

  • Screen and Web Usage: A setting between 100 and 150 DPI provides sharp visuals without inflating file size.
  • Print Production: A setting of 300 to 600 DPI is required to preserve fine line work and sharp text when output to paper.
  • Performance Considerations: Increasing the DPI quadratically increases memory usage. Rendering a multi-page PostScript document at 600 DPI or higher can consume several gigabytes of RAM during the Ghostscript execution phase.
